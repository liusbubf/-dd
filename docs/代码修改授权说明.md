# 代码修改授权说明（本地口令门禁）

> 目的：改代码前必须通过口令校验，防止误操作/未授权改动。口令**只存在本地未跟踪文件**，
> 绝不写进任何会被提交的源码——否则保护等于不存在。

## 一、口令放在哪

口令查找优先级（`tools/code_auth.py` 实现）：

1. 环境变量 `CODE_AUTH_PASSWORD`（最高优先，适合 CI/临时会话）
2. 项目根 `.env` 或 `backend/.env` 中的 `CODE_AUTH_PASSWORD=`
3. 项目根 `auth.local.json` 中的 `"code_auth_password"`

三者都在 `.gitignore` 中（`.env`、`auth.local.json`），不会被提交。
`.env.example` 与 `backend/.env.example` 只保留 `CODE_AUTH_PASSWORD=<your-own-password>` 占位符。

## 二、用法

```bash
# 首次/过期后：交互式输入口令，签发 30 分钟授权（写入 .code-auth）
python tools/code_auth.py

# 查看当前授权状态
python tools/code_auth.py --status

# 供 git 钩子调用（静默，退出码 0=通过 / 1=拒绝）
python tools/code_auth.py --check

# 手动撤销
python tools/code_auth.py --revoke
```

`--password <口令>` 可非交互传入，但会留在 shell 历史，不推荐。

## 三、有效期与令牌

- `.code-auth` 结构：`issued_at` / `expires_at` / `valid_minutes` / `sig`。
- `sig = HMAC-SHA256(口令, "issued_at|expires_at")`，改口令会立即让旧令牌失效。
- 有效期 **30 分钟**，过期后需重新运行 `python tools/code_auth.py`。
- 该文件在 `.gitignore` 中，不会入库。

## 四、提交钩子

`.githooks/pre-commit` 的行为：

1. 取暂存区文件名（`git diff --cached --name-only`）；
2. 若命中 `backend/`、`frontend/`、`app-client/`、`pc-client/`、`ws-scrcpy/src/` 任一目录 → 调用 `python tools/code_auth.py --check`；
3. 校验失败则**拒绝提交**，并提示运行 `python tools/code_auth.py`；
4. 只改文档（如 `docs/`、`README.md`）不触发门禁。

> **重要：当前仓库是纯源码快照，没有 `.git`，钩子尚未生效。**
> 将来执行 `git init` 后，再运行一次 `python tools/install_hooks.py`
> （它会设置 `core.hooksPath=.githooks`）才真正启用。
> 在此之前请自觉执行 `python tools/code_auth.py` 后再改代码。

Windows 提示：钩子是 `sh` 脚本，由 Git for Windows 自带的 bash 执行。如遇权限问题，
在 Git Bash 中执行 `chmod +x .githooks/pre-commit`。

## 五、为什么不能把口令写进仓库

- 仓库会被分发/克隆/截图，一旦入库等于公开；
- 即使删除文件，历史提交里仍可恢复；
- 口令入库后，任何拿到仓库的人都能"通过"门禁，门禁失去意义；
- 正确做法：只在本地 `.env` / `auth.local.json` 配置，示例文件用占位符。

## 六、轮换口令

1. 修改 `.env`（或 `auth.local.json`）中的 `CODE_AUTH_PASSWORD`；
2. 删除 `.code-auth`（或执行 `python tools/code_auth.py --revoke`）；
3. 重新执行 `python tools/code_auth.py` 签发新令牌；
4. 若曾把口令写进任何被跟踪文件，**立即轮换**并清理。

## 七、局限（请知悉）

- 这是**本地自觉型门禁**，不是强安全边界：知道口令的人可直接改代码，也可绕过钩子（`git commit --no-verify`）。
- 它防的是误操作与无意识改动，不防蓄意攻击；真正的权限控制应依赖代码托管平台的 MR 审批与分支保护。
