# V5 交付报告：渲染模式与分辨率

> 日期：2026-11-04
> 范围：只做 V5（渲染模式与分辨率）。V4 商业模型未改动。
> 结论口径：代码与接口层已验证；`adb` / redroid / physical 路径**未真机验证**；视频里的「旧版/新版渲染」在本项目**没有对应实现**，用「投屏渲染质量」替代，**未对齐视频**。

---

## 1. 可行性核对（结论来自代码，不是推测）

| 能力 | 代码位置 | 结论 | 说明 |
|---|---|---|---|
| 分辨率/DPI（physical 真机） | `orchestrator/physical.py` → `set_display` 使用 `adb shell wm size` / `wm density` | **真支持（未真机验证）** | 原先不保存原值，V5 新增 `orig_width/orig_height/orig_dpi`；失败会回滚 |
| 分辨率/DPI（Redroid） | `orchestrator/redroid.py` → `set_display` 需重建容器以改 framebuffer | **真支持但重（未真机验证）** | 重建约 10–30s，接口返回 `restart_required=true` |
| 分辨率/DPI（simulator） | `orchestrator/simulator.py` → `set_display` 只改内存态 | **真支持（模拟）** | 不涉及真实设备 |
| 分辨率/DPI（默认/基础后端） | `orchestrator/base.py` | **仅记录，不真实生效** | 没有真实设备可改 |
| `surfaceflinger` 相关 | 全仓库搜索无实现 | **完全缺** | 不声称支持；没有做任何相关开关 |
| 「旧版/新版渲染器」切换 | 无分支；只有 ws-scrcpy iframe 与截图链路 | **伪需求（本项目无对应实现）** | 不做空开关；改为投屏渲染质量 |
| 投屏质量参数 | `orchestrator/base.py` → `RENDER_QUALITY_PRESETS` | **真支持** | low/medium/high → `maxFps` / `bitrate` / `iFrameInterval`，写入 iframe URL |

## 5. 未验证项与风险

1. **`adb shell wm size/density` 未真机验证**：命令语法与回滚逻辑只经过代码审阅与 simulator 替代测试；需要 physical/redroid 环境实测。
2. **Redroid 改分辨率需重建容器**：耗时与业务中断未实测；前端只提示「约 10–30s」。
3. **视频「旧版/新版渲染模式」没有实现**：本项目不存在该分支，用「投屏渲染质量」替代，不能声称已对齐视频。
4. **scrcpy 流未验证**：本机 simulator 后端 + 无 ws-scrcpy 服务，`prepare` 返回 `ready=false`；页面会显示流不可用提示，不等于投屏功能冒烟通过。
5. **surfaceflinger**：无代码依据，未做任何实现或开关。
