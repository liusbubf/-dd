关键接口语义：

- `POST /devices/{id}/reset/restore-snapshot`：取最近一次 `status=ready` 快照；无快照返回 **409**，不返回成功；实体机不支持快照时按后端错误返回 **502**。
- `POST /devices/{id}/reset/wipe-data`：同步执行 clear_data 擦除；保留设备记录、分组、断占与 IP 绑定；失败返回 **502**。
- 两者都要求 `confirm_name` 与设备名完全一致（后端校验，不能只靠前端）；operator+；审计 `device.reset.restore_snapshot` / `device.reset.wipe_data`。
- `POST /devices/{id}/screen-lock` 与 `/unlock`：仅写审计 `device.screen_lock` / `device.screen_unlock`，返回体明确标注 `scope=client_overlay`、`server_occupancy=false`，**不建立服务端占用态**，不操作设备 keyguard。

## 三、遗留与风险

1. **历史设备无归属者**：存量 `owner_id` 为空，按「平台设备」处理，仅 admin+ 可管理共享。若要让原创建者管理，需要一次性归属回填（未在本批做，避免猜测归属）。
2. **「同租户」当前等于单实例**：项目尚无独立租户模型，因此共享范围为本实例内所有用户；`Device.tenant_id` 仅预留，任何接口都不读写。
3. **共享是可见性授权，不是写权限提升**：被共享用户按 viewer 级可见，写操作仍由现有 RBAC（operator+）决定；不会因为共享获得控制权。
4. **快照恢复只认 `ready` 快照**：最近一次失败/创建中的快照会被跳过，回退到更早的 ready 快照；完全没有 ready 快照时返回 409。若产品要求「最近一次必须是最新一条」，需另行定义。
5. **清空数据为同步 HTTP**：redroid/实体机擦除可能超过反向代理超时。前端已设 300s，部署时需同步调整网关超时，或后续改为「任务 + 轮询」（本批未改）。
6. **真机擦除未实测**：simulator 路径已由测试验证；redroid `_wipe_data` 与 physical `pm clear` 需要真机/容器环境执行确认，不能把代码审阅当作已验证。
7. **遮罩仅本端**：锁定状态存在浏览器 localStorage，不跨标签页/跨设备同步；这是「非服务端占用」的设计结果，不是缺陷。清屏锁按钮已从设备列表移除，仅在控制页提供。
8. **接口兼容性**：`POST /devices/{id}/snapshots/{sid}/restore` 现在要求 `confirm_name`，外部脚本若直接调用需补字段。
9. **列表可见性变化**：非 admin 用户不再看到「他人名下且未共享」的设备；历史平台设备（owner 为空）仍对所有人可见，以兼容旧数据。

## 四、V4 的前置条件（需要用户提供）

V4 为「订单 / 卡密 / 积分 / 代理」全模型 + 沙箱支付，不接真实支付。开工前请提供：

1. **套餐与续费规则**：续费单价（按天/按月）、试算公式、到期宽限期、退款/作废规则。
2. **卡密规则**：面额或天数、可用次数、有效期、是否可叠加、批量导入 CSV 的列定义。
3. **积分规则**：充值兑换比例、积分抵扣上限、积分有效期、退款是否退积分。
4. **代理规则**：邀请码生成规则、代理等级与返佣比例、返佣结算时点（订单支付/完成）、是否多级返佣。
5. **沙箱支付确认**：演示时需要哪些支付方式占位（微信/支付宝/余额），是否需要手动「标记成功/失败」后台入口。
6. **权限边界**：哪些页面仅 admin+ 可见，用户侧可见范围（自己的订单/卡密/积分/团队）。
7. **金额与币种**：确认全部使用整数分、单一币种（人民币），避免后期汇率模型。

> 真实支付网关（商户号、证书、回调域名、分账协议）不在 V4 范围；如后续要接，需单独立项。
