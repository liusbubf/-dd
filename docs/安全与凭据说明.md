# 安全与凭据说明

> 本文列明**哪些值必须由部署者自行配置**、**哪些是仅供演示的默认值**，以及轮换建议。
> 仓库内的 `.env.example` 只有占位符；真实凭据请写在 `backend/.env`（已被 `.gitignore` 忽略），
> 严禁写回任何被跟踪的文档或源码。

## 一、必须由部署者配置（无默认值 / 默认值不可用于生产）

| 配置项 | 位置 | 说明 |
|---|---|---|
| `CLOUD_JWT_SECRET` | `backend/.env` / k8s Secret | 签发 JWT 的密钥。默认值仅供本地演示，生产必须换成 ≥32 字节随机串 |
| `CLOUD_ADMIN_PASSWORD` | `backend/.env` / k8s Secret | 初始管理员口令。默认 `admin123` **仅演示** |
| `CLOUD_DATABASE_URL` | `backend/.env` / k8s Secret | 含数据库用户名口令的连接串，按 `<DB_USER>:<DB_PASSWORD>@<DB_HOST>/<DB_NAME>` 填 |
| `CLOUD_REDROID_HOST` | `backend/.env` | Redroid 宿主机地址（内网地址不要写进文档） |
| `DOCKER_HOST` | `backend/.env` | 远程 Docker API 地址，默认 `tcp://<REDROID_HOST>:2375`；**该端口无鉴权，必须限制来源 IP** |
| `CLOUD_ADB_PATH` | `backend/.env` | 本机 adb 可执行文件路径 |
| `CLOUD_SEED_USERS` | `backend/.env`（仅 SQLite 模式） | 预置团队账号的 JSON；只在本地开发用，不要写真实口令 |
| `CLOUD_SYNC_SERVER` | `backend/.env`（仅 SQLite 模式） | 中心服务器 API 地址；共享 PostgreSQL 时不需要 |
| `CLOUD_SEED_PWD_SUPERADMIN` / `_ADMIN` / `_OPERATOR` / `_VIEWER` | `backend/.env` | `tools/seed_rbac.py` 初始化四角色账号时读取；留空则自动生成 |
| `CLOUD_CORS_ORIGINS` | `backend/.env` | 允许的前端来源（JSON 数组）；默认仅本地 5173/4173，**不要用 `*`** |
| `CODE_AUTH_PASSWORD` | `backend/.env` 或 `auth.local.json` | 本地改代码口令门禁，见 `docs/代码修改授权说明.md` |

## 二、演示默认值（可直接跑，但必须知道它不安全）

| 项目 | 默认值 | 风险 | 何时必须改 |
|---|---|---|---|
| 管理员账号 | `admin` / `admin123` | 弱口令，公网暴露即被接管 | 任何非本机演示环境 |
| JWT 密钥 | 代码内默认串 | 可伪造任意用户 token | 生产 / 对外演示 |
| `CLOUD_DEVICE_BACKEND` | `simulator` | 假设备，无真实数据 | 接真机时改 `redroid`/`physical` |
| 数据库 | 本地 SQLite `cloud_platform.db` | 单文件、无并发、随目录分发 | 多人协作/生产改 PostgreSQL |
| Docker API `2375` | 无 TLS、无认证 | 等于把宿主 root 交出去 | 生产改用 TLS + 防火墙白名单 |

> 后端在 `debug=False` 且 `strict_security=True` 时，会对未修改的默认密钥/口令做启动校验并拒绝启动（见 `backend/app/config.py`）。

## 三、轮换建议

1. **JWT 密钥**：直接改 `CLOUD_JWT_SECRET` 并重启，所有已签发 token 立即失效（用户需重新登录）。建议每季度或发生泄漏时轮换。
2. **管理员口令**：改 `CLOUD_ADMIN_PASSWORD` 后重启（仅影响首启动播种）；已存在的库请到「用户管理」页面改密，或直接更新 `users` 表。
3. **数据库口令**：先在 PostgreSQL 侧改角色口令，再同步 `CLOUD_DATABASE_URL` 并滚动重启后端；避免长时间双口令并存。
4. **代码修改口令**：改 `backend/.env` 或 `auth.local.json` 中的 `CODE_AUTH_PASSWORD`，并删除旧 `.code-auth`（有效期最长 30 分钟，过期自动失效）。
5. **第三方/上游**：`ws-scrcpy` 为 vendor 上游（MIT），升级时以补丁方式记录本地改动，不要覆盖上游 `LICENSE`。

## 四、RBAC 初始账号（tools/seed_rbac.py）

| 账号 | 默认角色 | 默认用户名 |
|---|---|---|
| 超管 | `superadmin` | `shuntian` |
| 管理员 | `admin` | `admin` |
| 操作员 | `operator` | `operator` |
| 查看员 | `viewer` | `viewer` |

- 首次部署执行 `python tools/seed_rbac.py`（幂等，可重复跑；`--dry-run` 只看计划）。
- 口令来源：优先读 `CLOUD_SEED_PWD_*`；未提供时由 `secrets` 生成，打印到终端并写入 **本地未跟踪** 文件 `.seed_passwords.json`（已在 `.gitignore`）。
- 已存在同名账号时只补角色/启用状态，默认不覆盖原口令；确需重置请显式 `--reset-password`。
- 该脚本不写入任何文档或代码；`.env.example` 里只有占位符。角色边界见 `docs/RBAC权限矩阵.md`。

## 五、认证与网络边界（本轮收紧项）

| 项 | 现状 | 说明 |
|---|---|---|
| CORS | 默认仅 `http://localhost:5173`、`http://localhost:4173` | 生产用 `CLOUD_CORS_ORIGINS`（JSON 数组）显式配置，**不要 `*`** |
| JWT | HS256，有效期由 `CLOUD_JWT_EXPIRE_MINUTES` 控制（默认 720 分钟） | 无 refresh token；改 `CLOUD_JWT_SECRET` 会让所有已签发 token 立即失效 |
| Token 日志 | 响应体/请求体不写日志 | 只记录路由、状态、设备 id、操作人；不要自行在代码里 `log.info(token)` |
| 500 响应 | 统一 `{"detail": "服务器内部错误，请联系管理员"}` | 堆栈只进服务端日志，避免泄漏路径/SQL/版本 |
| 健康检查 | `/api/health` 返回 `status`（ok/degraded）与 `database` | Docker/adb 未纳入高频探针，按设备排障 |

## 六、仓库卫生约定

- `.env`、`auth.local.json`、`.code-auth`、`.seed_passwords.json`、`*.db`、`_attic/` 均已在 `.gitignore` 中忽略。
- 文档、脚本、示例配置中一律使用 `<DB_USER>` / `<DB_PASSWORD>` / `<INTERNAL_IP>` 等占位符。
- 提交前自检（在仓库根执行，应无输出）：
  ```bash
  grep -rnE "([0-9]{1,3}\.){3}[0-9]{1,3}" --include="*.md" --include="*.py" --include="*.yml" --include="*.yaml" .
  grep -rni "password.*=\s*[\"'][^<]" --include="*.md" --include="*.py" .
  ```
- 若不慎提交过真实凭据：立即轮换，再清理历史（仅删除当前文件不够）。
