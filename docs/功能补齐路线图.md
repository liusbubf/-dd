# 功能补齐路线图（以视频为准的全量对齐）

> 目标：视频里出现的功能全部对齐，缺失的从零搭建；质量要求为**产品级**，不是演示级。
> 依据：`docs/功能对照与补齐方案.md`（逐帧分析，85.9s，含时间点与证据帧）。
> 当前状态：P0 六项、P1 五项已完成（见 `docs/P1交付报告.md`）；本路线图从 V1 开始排批。

---

## 已确认决策（2026-11-04，用户拍板，后续按此实现，不再改模型）

1. **重置拆成两个独立入口**（V3 实现）：
   - 「恢复到快照」：恢复最近一次快照；
   - 「清空数据（保留设备）」：清用户数据但保留设备实体。
   - 两者都必须二次确认、写审计、失败如实返回，禁止假成功；UI 文案必须明确区分，避免误触清数据。
2. **设备分享 / 转移**（V3 实现）：先做**同租户内共享 + 可撤销**；跨租户转移暂不实现，数据模型预留字段但**不开接口**。
3. **清屏锁**（V3 实现）：先做**投屏层遮罩**（视觉锁定：显示锁定状态、禁止本端操作），不做后端占用态；后端 `unlock()` 保留，语义改为**解除遮罩**。

> V2 范围不变（登录增强 / 明暗主题 / 下载中心 / 工作台增强 + 浮窗多实例、多控坐标按设备分辨率），以上三项统一排到 V3。
> **状态（2026-11-04）：三条决策均已进入 V3 并完成落地**，实现与验证数据见 `docs/V3交付报告.md`；本文后续批次按 V3 → V4 → V5 执行。

## 0. 质量基线（先于任何新功能，所有新页面强制遵守）

### 0.1 页面四态（缺一不可验收）

每个新页面/新弹窗必须同时具备：

| 状态 | 要求 | 反例 |
|---|---|---|
| 加载态 | 骨架屏或带文案的 loading，禁止空白闪烁；超过 1s 的请求必须可见 | 打开页面一片白 |
| 空态 | 说明「为什么空 + 下一步做什么」，带主操作按钮 | 只显示「暂无数据」 |
| 错误态 | 展示可读原因 + 重试按钮；网络错误与业务错误分开 | 弹一个 `undefined` |
| 无权限态 | 按角色显示「需要 operator/admin」或直接隐藏入口；后端 403 要有专属文案 | 按钮点了报 403 |

### 0.2 设计令牌（已落地）

- 唯一来源：`frontend/src/styles/tokens.css`（已在 `main.js` 引入）。
- 新页面/组件**禁止写死 px 与色值**，只能使用 `var(--sp-*) / var(--radius-*) / var(--font-*) / var(--color-*) / var(--shadow-*)`。
- 间距只用 4 的倍数；字号只用 12/13/14/16/20/24。
- 暗色主题只通过 `html.dark` 覆盖同一批 CSS 变量，**不做第二套样式表**；切换状态存 localStorage。
- 存量页面在对应批次内顺手替换令牌，不做一次性大重构。

### 0.3 列表/表格/交互约定

- 表格/列表必须支持：分页（或明确的「加载更多」）、排序、筛选（至少关键字 + 状态）。
- 破坏性操作（删除/重置/转移/清空/解绑）必须二次确认，确认文案写清影响范围。
- 异步操作必须有进度与结果反馈：按钮 loading、任务进度（轮询或 WS）、成功/失败 toast、失败可重试。
- 空值统一显示 `—`，不显示 `null/undefined`。

### 0.4 接口与后端约定

- 所有新接口入参必须有 Pydantic 模型，带边界（长度/范围/枚举）；禁止裸 `dict`。
- 写接口统一 `require_operator` 及以上；用户/审计/商业化配置类 `require_admin`。
- 写操作必须写审计（`record_audit`），包含操作人与目标。
- 每个新接口同步补 `backend/tests/` 用例；数据库改动只走 `ensure_schema()` 幂等迁移（SQLite/Postgres 双通）。
- 删除一律软删除/归档（`_attic/` 或状态位），不做物理删除（云盘文件物理删除属既有例外，保留）。
- 不修改 `orchestrator/redroid.py`、`orchestrator/preview.py` 的整体结构；新能力以新增方法/新模块接入。

### 0.5 体验细节清单（每批交付必须逐项勾）

- [ ] 骨架屏/加载文案
- [ ] 乐观更新或「提交后即反馈」，失败回滚
- [ ] 快捷键（至少 Esc 关闭、Enter 确认）
- [ ] 键盘可达性（Tab 顺序、focus 可见、弹窗 focus trap）
- [ ] 错误可恢复（重试按钮/保留已填内容）
- [ ] 长列表虚拟化或分页
- [ ] 移动端/窄屏不横向溢出
- [ ] 暗色主题下对比度可读

### 0.6 验证口径（必须如实标注）

- 「已验证」= 跑了 `pytest` / `pnpm run build` / 浏览器实际点击三者中至少对应项，并给出数据。
- 只读代码得出的结论写「代码审阅，未运行」，不写成已验证。
- 每批交付报告必须列出：已验证项、仅构建验证项、未实测项。

## 1. 合规与商业边界（写死，不接受口头例外）

### 1.1 不做（合规红线）

| 功能 | 处理 | 合规等价替代 |
|---|---|---|
| 破解器 / 过检测 / 反作弊对抗 | **不做**，不加入口、不留接口 | 多实例环境隔离、缓存清理、环境重置、网络隔离 |
| 改机（批量伪造 IMEI/IMSI/序列号/Android ID） | **不做** | 指纹「只读展示 + 重新随机生成」（仅自有虚拟设备）、快照回滚、一键新机 |

> 页面不得出现「破解器」「改机」空按钮；需要展示能力边界时，用说明文案而不是可点击入口。

### 1.2 商业化：做完整模型，不接真实支付

- 订单 / 卡密 / 积分钱包 / 代理返利：**数据模型 + 业务逻辑 + 页面 + 测试全部做**。
- 支付抽象 `PaymentProvider`：
  - 默认实现 `SandboxProvider`（本地记账、可手动标记成功/失败，供演示与测试）。
  - 真实网关适配器只保留接口与配置位（`WechatPayProvider` 等），**不接通道、不落密钥**。
- 分账字段预留：订单表含 `channel / channel_txn_id / settled_at / commission_rate / agent_id / commission_amount`；代理返利按规则计算并写流水，不实际出款。
- 所有金额用整数分（`amount_cents`），禁止浮点。

### 1.3 设备分享 / 转移：按租户/用户边界

- 已引入设备归属：`Device.owner_id` + `device_shares` 表（被共享人、授予人、创建/撤销时间）。
- 分享/撤销接口校验「当前用户是否为归属人或 admin+」，越权 403；撤销后立即失效。
- 同租户共享已在 V3 落地；跨租户转移只预留 `Device.tenant_id` 字段，**不开接口**。
- 转移若未来开启，需写双向审计（转出人/接收人/操作人）。

## 3. 排批与交付规则（D）

### 3.1 批次顺序

1. **已完成**：P0 六项 + P1 五项。
2. **V1（入口级，看得见）**：V1-1～V1-13、V1-16。先做浮窗投屏与尺寸滑杆，再做多控/全屏/工作台，最后工具栏、应用库、推送进度、清屏锁。
3. **V2（账号与外壳）**：验证码、上次登录、主题、下载中心、首页、侧栏偏好、云盘细节、VPC 细节（已交付）。
4. **V3（重置 / 共享 / 投屏遮罩）**：三条已确认决策落地（已交付）。
5. **V4（商业化沙箱）**：订单 → 卡密 → 钱包 → 代理；**不接真实支付**。
6. **V5（真机能力）**：先验证渲染模式与分辨率，再决定分身；不新增后端渲染器。

### 3.2 硬规则

- **一批交付一次**，不并行改同一块 UI（尤其 `Control.vue`、`Devices.vue`、`MainLayout.vue`）。
- 每批开始前先写「本批范围 + 验收口径」，结束后给「完成度 + 验证数据 + 未实测项」。
- 每项完成即跑 `pytest` 与 `pnpm run build`；失败停下说明，不带红色构建进下一项。
- 每批交付附「体验细节清单」（见 §0.5），逐项勾选并说明未做原因。
- 新页面必须使用 `tokens.css`；发现写死色值/px 视为未完成。
- 后端改动只走 `ensure_schema()`；每个新接口配 pytest；写接口 operator+ 且审计。
- 文档与代码不一致时，以代码核实结果为准，并在交付报告中写出偏差。
