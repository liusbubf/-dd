## 1. 六项完成度

### V1-1 浮窗投屏 + 尺寸滑杆 —— 约 85%

- **链路选择**：采用「HTTP 轮询帧（`/devices/{id}/screenshot` + `preview_hub` 帧缓存）」，未用 ScrcpyPlayer。原因：scrcpy 依赖宿主机 ws-scrcpy 服务就绪，simulator/未部署环境直接不可用；轮询帧两条后端都能稳定出图。
- 新增 `components/FloatingPlayer.vue`：Teleport 到 body、非模态、标题栏拖动、实时刷新（300ms，页面隐藏时暂停）、刷新按钮走 `fresh=true`、可在浮窗内跳「新页打开」、Esc 关闭。
- 尺寸：480 / 720 / 1080 三档 + 360–1200 连续滑杆（步长 60），显示宽度 = 尺寸 / 2；**上次尺寸写 localStorage 记忆**。
- 入口一致性：设备表格行与设备卡片同时提供「浮窗」+「操控（新页）」，两种打开方式并列且位置一致。
- 状态：加载态、无画面空态、首帧失败错误态（带重试）；已有画面时短暂失败保留旧帧，避免闪烁。
- 未做：同一时间只支持 1 个浮窗（未做多开）；未做工具栏级“全局打开方式”偏好设置。

### V1-2 多控 / 全屏 —— 约 90%

- 宫格页勾选 ≥2 台设备后进入「多控模式」：主控画面上的点击 / 滑动 / 按键 / 文本通过现有 `/api/batch/*` 广播，逐台结果来自 `BatchResult.details`。
- 坐标口径：前端把主控设备坐标换算到后端 `_scale` 的 1080×1920 基准，再由后端按各设备分辨率折算（非 9:16 设备仍有细微偏差，见风险）。
- 反馈：进行中、全部成功、部分成功（含逐台失败原因）、**失败项一键重试**、结果 CSV 导出。
- 单格全屏：Fullscreen API + 固定覆盖层双保险；Esc 退出；退出按钮常驻。
- 控制条不遮挡：全屏容器为纵向 flex，顶栏独立一行、画面区 `flex:1` 居中，二者不重叠。

### V1-3 设备工具栏 —— 约 90%

- 「显示 IP」开关（表格列 + 卡片 IP 行），偏好持久化。
- 排序：默认（运行中优先 + 剩余时长）、在线优先、分组、剩余时长、名称，偏好持久化。
- 右键菜单（表格行 + 卡片均可右键）：重启、截图、清屏锁、详情、移入分组、绑定 IP。
- 左侧设备树：`/groups/tree` 渲染分组树 + 计数 + 未分组/全部节点、按子树筛选（父组包含子组）、可折叠、当前筛选可清除。
- 绑定 IP 弹窗复用 `GET /ips?status=available` + `POST /ips/{id}/bind`，空态/加载态/错误态齐全。
- 未做：树内“他人分享”节点（依赖尚未实现的分享能力，先不放假入口）。

### V1-4 应用库 / 公共安装包 / 推送进度 —— 约 85%

- **任务体系不重复造**：核实后复用 `CloudFile(category=apk)` 存储 + `cloud_push_jobs` 下发任务表，未新建第二套任务体系。
- 新增「应用库」页：APK 上传（上传进度）、配额显示、搜索、公共/私有标记（admin 才能改）、上传人/时间、下载、单文件推送多设备（目标设备多选 + 远端目录）、只读角色的无权限提示。
- 新增「推送进度」页：任务列表、进行中/全部成功/部分成功/失败/中断状态、2.5s 自动轮询、详情抽屉逐设备/逐文件状态与失败原因、导出 CSV。
- **失败重试接口**：`POST /cloud-disk/push/{job_id}/retry`，复用同一张表，新任务只包含失败条目（不重复推成功项），operator+ 并写审计 `cloud.push.retry`。
- 四态：加载 / 空 / 错误（可重试）/ 无权限（只读提示）均已实现。
- 未做：APK 包名/版本/图标解析（需要 aapt/androguard 等额外依赖）；应用库暂为表格视图，未复刻视频里的卡片墙。

### V1-5 清屏锁 —— 约 75%

- `DeviceBackend.unlock()`：基类默认成功（Simulator 无真实锁屏）；Redroid / physical 各自实现 `wm dismiss-keyguard` + `input keyevent 82` 兜底。
- `POST /devices/{id}/unlock`：operator+、Pydantic 路由参数、失败如实映射（不可达 503 / 命令失败 502），成功写审计 `device.unlock`。
- 前端入口：设备表格行、卡片下拉、右键菜单三处一致。
- **偏差要写明**：需求里“锁定时禁止其它写操作”没有实现。当前后端没有可靠的“设备是否处于锁屏态”的检测能力（各 ROM/Redroid 返回不一致），贸然用一个内存标记禁止写操作会造成误锁；建议产品明确“锁定”是指设备锁屏态还是平台侧租户锁，再决定是否落 `Device.locked` 字段与全局写拦截。

### V1-6 推送与体验细节 —— 约 80%

- 批量/推送统一：进行中、成功、失败、部分成功四类反馈；失败可重试；结果可导出（多控结果 CSV、推送明细 CSV，均带 BOM 兼容 Excel）。
- 推送任务被服务重启中断后显示「已中断」而非消失（沿用 P1 落库能力，前端补状态映射）。
- 未做：设备页的“批量启停/重启”快捷工具条（路线图 V1-16 项，不在本轮 6 项内）。

## 3. 体验细节清单（哪些做到、哪些只是“有入口”）

- 加载/空/错误/无权限四态：应用库、推送进度、绑定 IP、浮窗均已实现；设备树为空时退回空态。
- 骨架屏：未做，当前用 `el-icon is-loading` + 文案，属于“加载态”但不是骨架屏。
- 乐观更新：未做。推送提交后跳转进度页靠轮询，不上乐观进度。
- 快捷键：Esc 关闭浮窗、Esc 退出全屏（非 Fullscreen API 场景）；未做全局快捷键。
- 键盘可达性：全部使用原生 `button` / `el-button`，浮窗可聚焦响应 Esc；未做完整 focus trap 与 aria 标注。
- 错误可恢复：浮窗、应用库、推送详情、绑定 IP 均有重试按钮，错误文案取后端 `detail`。
- 二次确认：删除 APK 有确认；重启/清屏锁未加确认（非破坏性），符合“破坏性才二次确认”。
- 写接口基线：unlock / retry 均 operator+ + 审计；路由入参沿用 Pydantic / Query 约束。
- 令牌：新增组件（FloatingPlayer、AppLibrary、PushProgress、设备树/右键菜单）颜色、间距、圆角、字号全部走 `tokens.css` 变量；既有 `Devices.vue` 中遗留少量硬编码色值未顺手改动，避免无关 diff。

## 4. 未完成项与风险

### 需要用户拍板
1. **“重置”定义**：实体机行上的「重置」目前沿用一键新机语义（换指纹/重建），与“恢复出厂/清数据”不是一回事；需要明确产品语义后再实现第二套能力。
2. **设备分享 / 转移归属模型**：租户/用户边界、转移后云盘与任务归属、审计归属都未定；当前不做入口，避免越权。
3. **“锁屏期间禁止其它写操作”**：如上，需先定义“锁定”是设备锁屏态还是平台锁定态。

### 已知差距
- 浮窗单实例（视频若要求多开需补窗口管理）；全局“打开方式”偏好未做。
- 应用库缺少 APK 元数据（包名/版本/图标），卡片墙未做。
- 多控坐标以 1080×1920 为基准；对 16:10、平板类分辨率会偏。建议后续把 batch 接口改为接收 0–1 归一化坐标，由后端按设备分辨率换算（需要动 `routers/batch.py`，本轮按约束未改结构）。
- fresh 限流为**单进程内存态**，多 worker/Uvicorn 多副本下不共享；集群级限流需 Redis。
- 前端未浏览器实测：全屏在部分浏览器需要用户手势触发（本实现点击按钮触发，满足）；iOS Safari 的 Fullscreen API 支持不全，已回退覆盖层但未实测。

### 风险
- 推送重试若安装包在本轮被删除会返回 400（已显式校验，不会静默失败）。
- 绑定 IP 依赖 IP 池中存在 available 资源；当前弹窗只列 available，若要“解绑/换绑”还需补一个解绑入口（右键菜单暂未放，避免误操作）。
- 应用库与云盘页共用同一份数据，入口有两个；V2 建议合并或在云盘页加“去应用库”交叉链接，避免用户困惑。
